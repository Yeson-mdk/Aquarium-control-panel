# 记忆系统架构（2026-11-12 现网版）

> 配套文档：`docs/记忆升级计划.md`（阶段一到四的演进与待办）。本文描述**当前已上线**的架构。
> 核心设计原则：**分层 + 不真删 + 串场隔离 + 失败不劣于现状**。

## 一图流

```
                    ┌────────────── 白天（边聊边记）──────────────┐
                    │                                            │
  QQ 消息 ──→ ① 原始层：qq-chat-<peer>.jsonl（全记录，按会话分文件）
                    │      └→ ⑦ 好友档案 friends.mjs（一人一份，群消息全落）
                    │      └→ ⑧ 号主 facts（「关于你的事」）
  B站生活 ──→ ② 记忆流：memories.json（零碎条目，kind 分类）
  晨间计划 ──→    计划反馈记忆（「想干什么→跑完怎样」，无 peer 钥匙）
                    │                                            │
                    ├────────────── 每晚睡前（对账流水线）──────────┤
                    │                                            │
                    │  ⑨ 反思（22 点后）：睡前想一遍今天 → kind:self
                    │  ⑩ 洞察归纳：LLM 从记忆里抽结论（带依据 id，可推翻旧洞察）
                    │  ⑪ 整理：零碎合成印象（from=N 条）、太久没想起的 → ⑫ 淡忘档案
                    │  ⑬ 群日结 / 朋友圈近况：每个群、每个朋友每晚各结一份
                    │  ⑭ 记忆对账自检：该想起的都在、陷阱条目没串出来
                    │                                            │
                    ├────────────── 随时（被问到才想起）───────────┤
                    │                                            │
  她回话时 ──→ ⑮ recall()：对记忆流打分取 top-N，拼进提示词
                    │      洞察（kind:self）打 0.7 折——猜想不盖过亲历
                    │      ⑯ 淡忘档案 memdb：忘了的原文，面板搜得回来
                    └────────────────────────────────────────────┘
```

## 各层职责与落盘

| # | 层 | 文件 / 模块 | 存什么 | 生命周期 |
|---|---|---|---|---|
| ① | 聊天原文 | `data/qq-chat-<peer>.jsonl` | 每条消息原文（ts/from/name），群聊全记录 | 5 天内全文进提示词（`ctx.days` 热调），更早的只靠上层记忆 |
| ② | 记忆流 | `panel/memory.mjs` → `data/memories.json` | 零碎条目：`watch`(B站见闻) `session` `social` `self`(洞察/反思) `fact`；字段 `imp` 重要度 1-5、`keys` 串场钥匙（`g:群号`/`p:QQ号`）、`n` 想起次数、`from` 合成来源、`dead` 推翻标记 | 活着的进召回；太久没想起 → 淡忘 |
| ③ | 印象 / 日结（压缩层） | 同上，`kind: gist / chat` | gist = 她自己把零碎概括成的印象；chat = 每晚的对话日结（号主/群/好友） | 日结几天后合成印象；印象是长期底色 |
| ⑨⑩ | 洞察层 | `kind: self`（在记忆流里） | 每晚反思结论 + 洞察归纳（最多 2 条/晚，每条带依据消息 id 和 why） | 被新证据推翻 → `dead` 标记，不再召回但面板可翻回；待审池开着则先进池由号主放行 |
| ⑫ | 淡忘档案 | `panel/memdb.mjs`（node:sqlite 镜像） | 忘掉的原文**只增不删**，跟记忆流实时镜像 | 不会自己想起来；面板搜索翻得回来 |
| ⑦ | 好友档案 | `panel/friends.mjs` | 一人一份：称呼、群、好感（fav）、近期 notes；群日结、朋友圈近况 | 按人隔离，`keys` 串场钥匙保证 A 群的事不在 B 群冒出来 |
| ⑧ | 号主 facts | `qq/facts`（记忆页「关于你的事」） | 她记的关于号主的事（偏好、身份、约定） | 聊天时 + 每晚整理记的，删了她就忘了 |
| — | 人设演进 | `panel/mind.mjs` | persona 补丁（每 14 天按她的记忆微调，只依据 B站生活 + 跟号主的私聊，公共模式不进）；内心心情/兴趣/饱和度 | 晨间计划会把 persona 摘要当输入 |

## 召回：她怎么「想起来」

`memory.recall(query, opts)` **同步**执行（聊天热路径上，不能慢），对活着的条目打分：

```
S = 1 × 新近度 + 1 × (imp/5) + 2 × 相关度（关键词 + 二字片段重合）
```

- 相关度权重最高（×2）：想起来的必须是对得上的，不是最新的
- `kind:self`（洞察/反思）整体打 **0.7 折**（`tuning.memory.selfDiscount` 热调）：猜想不该和亲历同权重出场
- **串场隔离**：`keys` 带群号/QQ号，A 群聊到的熟人不会在 B 群或私聊里冒出来；号主的事不进群聊
- 召回结果 + 5 天内聊天原文 + 印象，一起拼进回复提示词

## 每晚对账流水线（22 点后）

1. **反思**：睡前把今天想一遍，结论落 `kind:self`（「睡前想螺旋星轨」这种）
2. **洞察归纳**：LLM 从近期记忆抽结论，每条必须带依据 id（凭空的不收），可同时申请推翻过时的旧洞察（`retire`）
3. **整理**：相近零碎合成印象（记 `from: N 条合成的`）、太久没想起的淡忘进 memdb 档案
4. **群日结**：每个群一份当天摘要（原文 5 天后消失，靠这个长记性）；朋友圈近况汇总
5. **对账自检**：recall-check 跑一遍——该想起的条目都召回得回来、陷阱条目（别群的私事）没串出来

## 面板（记忆页，2026-11-12 改版）

「她自己的」四个子标签：**日子**（经历，按天分组，计划反馈带 📋）→ **想法**（洞察与内心，待审池置顶，被推翻的沉底折叠）→ **印象·日结**（压缩层 + 手动整理按钮）→ **档案**（淡忘原文搜索）。另有「关于你的事」「朋友们」两个大标签。所有条目可改（改过算刚想起来，寿命重算）可删，洞察可放行/丢掉。

## 与晨间计划（阶段三 A段）的接口

- **输入**：persona 摘要 + 最近 5 条洞察 + 昨天各动作计数 + 待办 → 生成今天每个时辰的类型和 goal
- **输出**：带 goal 的时辰跑完落一条反馈记忆（`kind: watch/social`，imp 2，**不带 peer 钥匙**——是她自己的经历，不是哪个对话的事）
- 闭环：反馈和元复盘（B段）都落 `kind:self`，经洞察栏**自动流进第二天的计划输入**——计划会自我微调

## 边界与原则（踩过的坑沉淀）

- **不真删**：淡忘进档案、推翻打 dead 标记，原文永远翻得回来
- **失败不劣于现状**：模型挂了 → 洞察不写、整理照旧、计划回退纯时辰表
- **凭证不进记忆**：cookie/密码类绝不记（`looksInjected` 拦一道）
- **换说法翻不到**是已知短板：同义不同词的旧事可能想不起来——这是阶段四（向量检索）要解决的事，前几阶段跑顺前不动
