## 一句话总览

「养鱼」：一个跑在 NAS Docker 里的单进程 Node 应用（panel/），养着一个有记忆、有性格的 QQ 小号——
她会自己刷 B站（时辰制自动养号 + 晨间计划）、在 QQ 里聊天（人设 + 好感 + 朋友档案）、每晚整理记忆写日记。
**零 npm 依赖**（手写 PNG/JPEG/GIF 解码器、node:sqlite），数据全是本地 JSON/JSONL，一个容器全装下。

## 运行形态

```
docker-compose.yml
├─ panel   (node:24-alpine, 端口 8899)   ← 全部代码和逻辑都在这个进程里
└─ napcat  (QQ 协议端, 端口 3001/6099)   ← 只做 QQ 收发，panel 用 WebSocket 连它
```

panel 进程内部跑着三样东西（[panel.mjs:661-667](../panel/panel.mjs#L661)）：

1. **HTTP 面板**（`server.listen`）——浏览器管理页 + 全部 API
2. **自动养号调度器**（`auto.startScheduler()`）——每 30 秒一拍 tick（[autopilot.mjs:30](../panel/autopilot.mjs#L30)）
3. **QQ 连接**（`qq.start()`）——连 NapCat 的 WebSocket，收发消息

## 分层架构（依赖方向自上而下，无循环）

```
                 panel.mjs（HTTP + 启动）
                      │
      ┌───────────────┼────────────────┐
   autopilot.mjs   qq/index.mjs      其余面板页后端
   ── plan.mjs        │              （stickers/health/…）
   （计划→执行）    brain.mjs ★（persona+闸门+管线）
                      │
                      ├─ prompts.mjs（规矩文本）＋ tools.mjs（工具）
                      │
      ├── social / notify / mind / memory / friends / fav ──── 域模块层
      │               │
      ├── bili / browser / memeimg / gif / sky / dsh ───────── 外部接口层
      │               │
      └──────── llm.mjs ──────────────────────────────────── 模型调用层
                      │
                 store.mjs（config/state/secrets/日志，唯一落盘层）
```

四条铁律（读代码前先记住）：

1. **store.mjs 是唯一的状态入口**——任何模块要读写 config/state 都经过它，没有第二套
2. **llm.mjs 是唯一的模型出口**——主模型/视觉模型/便宜档全走这，别处不直连 API
3. **依赖方向单一**——上层 import 下层，无循环；拆分后的转出口（brain→tools/prompts、autopilot→plan）保持了外部引用不变
4. **域模块不 import qq/ 子树**——现存唯一例外 friends→qq/owner（历史遗留，顺手时可清）

拆分口径（2026-11-13）：
- **brain 三件套**：改规矩只动 prompts.mjs；加/改工具只动 tools.mjs；brain.mjs 留「怎么想、怎么回」
- **autopilot/plan 分家**：plan 管「今天排什么」（含 markExpired 错过标记 → 驱动重排），autopilot 管「怎么执行」
- 外部消费面一律不变：qq/index 和测试仍 `import brain`、panel 仍 `import autopilot`，转出口兜底

## 三条主链路走读

### 1. QQ 聊天链路（她怎么回话）

```
NapCat WS → onebot.mjs（协议） → qq/index.mjs
  ├─ imageSegments 挑出图 → memeimg.cachedSee（指纹命中=零视觉调用，未命中→llm.seeImage）
  ├─ 攒批（群聊 2.5s）→ brain.topicScoreMessage 打分闸（纯情绪梗图/无效短句拦在门外）
  └─ brain.reply：
       system = persona(persona.mjs 从角色卡抓) + 心境补丁 + prompts.mjs 的规矩(按 私聊/公共/群 选一份，{FREQ} 按调参替换)
       + 摘要 + 历史 + 此刻状态（天气/好感/待审）
       → 主模型（可带 tool_calls）→ tools.mjs 的 runTool 分发
       （send_sticker 有自拍池硬闸；send_selfie 空池会留日志）
       → tidyReply 剥标记 → 发送（表情/语音跟回复一起发）
```

### 2. 自动养号链路（她怎么自己过活）

```
autopilot tick（30s 一拍）
  ├─ pause 检查（号主叫停）→ 解除时边沿触发重排
  ├─ 派活检测（executor=bot 的新任务）→ 触发重排
  ├─ plan.markExpired 标错过格子（今天的也在内）→ 有新标的就重排剩余时辰（每天最多 2 次）
  ├─ plan.morningPlan：第一个时辰开窗前生成（人设摘要+最近洞察→时辰表+goal，白名单护栏+回退静态表）
  ├─ 到点的格子 → autopilot.executeSlot：rest 歇着、diary/check 走专项、其余 runSession
  │    （真的看视频、随缘点赞、按计划评论；带 goal 的格子跑完 plan.recordSlotFeedback 写反馈记忆）
  ├─ social.checkInbox：定期看「回复我的」，自己决定回不回
  ├─ 派活 runTask：QQ 里接的活执行完汇报
  └─ 22:00 maybeNightlyDiary：群日结→洞察→睡前反思→日记（记忆系统，不吃总开关）
```

总开关（cfg.enabled）只管上面加粗的自动部分；QQ 聊天、号主点的活（bg.mjs）、面板手动「现在刷一轮」、22:00 记忆套件、正在跑的一轮都不受它管。

### 3. 记忆链路（她怎么记住事）

```
聊天/刷B站 产生记忆 → memory.mjs（imp 分级、peer scope 钥匙）→ memdb.mjs（sqlite 镜像，只增不删）
每晚 mind.mjs：反思（昨日输入→新洞察）· 洞察喂给晨间计划和心境
朋友档案 friends.mjs 按人全局（在哪个群都认得这个人）；聊天原文按对话 scope 放行（群/好友/私聊互不串）
回忆时 recall.mjs 查询 → LLM 精排（scope 过滤后的候选）
```

## 部署要点（和代码同等重要）

- 只改 `panel/`，上传 NAS 直接从 panel/ 拿（**不再同步 clone/**）
- 容器重启即生效，无构建步骤；改了前端 app.js 浏览器要强刷（Ctrl+F5）
- 时区必须 Asia/Shanghai（她的作息全看它）；8899 面板无登录保护，只留局域网
