# 看图升级：可选计划（2026-11-12 立项存档）

> 配套：看图 1.0 → 2.0 的第 1、2 层（结构化转译 + 梗图指纹库）已实施，见 `docs/记忆升级计划.md` 同期记录与 `panel/memeimg.mjs`。
> 本文档只存**没做的那层**：第 3 层「按需细看」。原则跟阶段四一样——有线上证据才动手。

## 第 3 层：按需细看（二段式看图）

**它是什么**：第 1 层的结构化描述是「一次看图伺候所有人」——闸门判定 + 回话上下文共用一份 `画面`（一句话）。绝大多数图这就够了；但**内容图**（截图、照片、聊天记录）有时真的需要细节才能接话，一句话描述会在「真的要回」的时刻显得空泛。

**方案**：过闸且她真的要开口、且 `kind` 是内容图/截图时，**第二遍定向细看**——带着「这是截图，把关键内容读出来」这类定向提示再调一次视觉模型，细看结果只进这一次的回复上下文，不落库、不进闸门。

**为什么不默认上**：
1. 慢：第二遍调用串在她回复前面，回图多等一轮视觉（几秒）
2. 贵：视觉调用翻倍（只对过闸的内容图，但仍是增量）
3. 没有证据说需要：第 1 层把 `图上文字` 逐字保下来之后，大部分「接不上话」的场景已经解决——题眼是字，不是画面细节

**触发条件（什么时候把它捡起来）**：线上出现「她回了图，但回得明显空泛/答非所问」的案例，且那张图的 `图上文字` 是空的（排除题眼缺失的情况）。连续出现几次，再来做这层。

**实现提示（到时候照抄）**：
- 位置：`brain.mjs` 回复路径上、主模型调用之前；`kind∈{照片,截图,聊天记录}` 且 `scene.length < 60` 时触发
- 预算：走 `tag: 'vision2'`，非 essential；每天上限（todayCounts 新 kind）挡一道
- 结果只拼当次提示词，不写聊天记录（`[图片：…]` 占位符保持第 1 层的样子，免得第二天的她看到两份不一样的描述）

## 不做的（存档免议）

- **WebP 解码进指纹库**：QQ 偶发 webp，命中不了就照常走视觉调用，不劣于现状；等 webp 占比真的高再说
- **渐进式 JPEG（progressive）解码**：解码器只写基线；解不动 → 跳过指纹，走视觉。同上
- **外部梗库对接**：梗图指纹库是「她自己的经历」（见过什么、谁常发），跟 cnmeme 那种「词义百科」是两个正交的东西，不合并、不互通
