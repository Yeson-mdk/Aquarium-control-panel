# 把她装进树莓派：视觉 + 听觉 + 嗓子的方案

> 这是一份**方案文档**（还没动手做）。目标：做一个摆在桌上的实体「蓝色大肥鱼」——能听（麦克风）、能看（摄像头）、能说话（喇叭），性格、记忆、B站生活还是现在这一套，不多出一套人格来。

---

## 一、总体思路：云端大脑 + 本地身体

她现在的「脑子」本来就全是接口调用：LLM 是 DeepSeek 的 API、看图走 ModelScope、语音是 edge-tts 生成的。所以**脑子不用搬家**——继续跑在 NAS/云上，树莓派只当「身体」：

```
┌─────────────── 树莓派（身体）───────────────┐        ┌──── NAS / 云（大脑，现有的）────┐
│                                              │        │                                 │
│  麦克风 ──► 唤醒词检测 ──► 语音识别(ASR) ─────┼──────► │  panel 新增一个「身体桥」接口    │
│                                              │  HTTP  │   ├─► brain.reply()（人设/记忆） │
│  摄像头 ──► 拍一张 ──────────────────────────┼──────► │   ├─► llm.seeImage()（看图）     │
│                                              │        │   └─► LLM / ModelScope（API）   │
│  喇叭   ◄── edge-tts 合成音频后本地播放 ◄────┼──────  │                                 │
└──────────────────────────────────────────────┘        └─────────────────────────────────┘
```

好处：

- 树莓派只需要干「收音、拍照、放音」这种轻活，**Pi 4 就够，不用指望板子跑大模型**；
- 人设、好感、记忆、追加式上下文、她刷 B站 的生活——硬件端和 QQ 端用的是**同一个脑子**，不会出现「桌上的肥鱼和 QQ 里的肥鱼不认识彼此」；
- QQ 那边照常跑，等于她多了一个「肉身」，不是搬家。

## 二、硬件清单

### 推荐配置（Pi 5，一步到位）

| 部件 | 建议 | 大致价位 | 说明 |
| --- | --- | --- | --- |
| 主板 | 树莓派 5（8GB） | ￥600~700 | 跑 ASR/唤醒词富余；Pi 4（4GB）也能跑，识别会慢一点 |
| 存储 | 32GB A1 微型 SD 卡 | ￥40 | 系统 + 模型文件（模型 ~200MB 级） |
| 麦克风 | ReSpeaker 2-Mic HAT（帽子板）或 USB 全向麦 | ￥60~150 | 帽子板省地方、双麦抗噪好；USB 麦省事，认准「降噪/全向」 |
| 喇叭 | MAX98357A I2S 功放板 + 3W 小喇叭 | ￥20~40 | 配 HAT 麦时走 I2S；懒人方案：USB/3.5mm 小音箱直接插 |
| 摄像头 | CSI 摄像头模块 v3（官方）或 USB 摄像头 | ￥60~250 | USB 头最省事；CSI 夹排线要注意方向 |
| 电源 | 官方 5V/5A（Pi 5） | ￥80 | 供电不足是树莓派玄学问题的第一大来源 |
| 其他 | 外壳、散热风扇 | ￥30~60 | 长期开着必须有散热 |

**合计约 ￥900~1200。** 想先试水：拿手头任何 Pi + USB 麦 + 旧音箱就能跑通整条链路，之后再补件。

## 三、软件选型

原则：**能在 Pi 上离线跑的用离线（唤醒、识别），要联网的走现有 API（对话、看图）**。

| 环节 | 选型 | 跑在哪 | 理由 |
| --- | --- | --- | --- |
| 唤醒词 | sherpa-onnx 的 keyword spotting（自定义「肥鱼」「小肥鱼」） | Pi 本地 | 免费、中文、CPU 实时；备选 Picovoice Porcupine（效果最好，免费档需注册） |
| 语音识别 | sherpa-onnx + paraformer-zh 流式模型 | Pi 本地 | CPU 上中文流式识别的首选，说完即出字；备选 Vosk（更省资源、精度略低） |
| 对话 | 现有 panel 的 brain.reply() | NAS/云 | 人设、好感、记忆全部复用，不另起炉灶 |
| 看图 | 现有 ModelScope Qwen 视觉通道 | 云 API | Pi 拍照 → 传 panel → seeImage，跟 QQ 看图同一条路 |
| 说话 | edge-tts（python 库，Meijia 音色） | Pi 本地合成 | 和她现在 QQ 语音是**同一个声音**；断网时降级 sherpa-onnx 中文 TTS（音色会不一样） |
| 命令词 | 本地小词表（音量/闭嘴/睡觉） | Pi 本地 | 「别吵」「睡觉了」这类不需要过大脑，本地直接执行，响应快也不花 token |

Pi 侧用一个 Python 常驻程序串起整条流水线（`pyaudio`/`sounddevice` 收放音、`picamera2` 拍照）。

## 四、和现有 yangyu-bot 怎么接

要新写的东西不多，核心就一个**「身体桥」**：panel 加一个新模块（比如 `panel/hardware.mjs`，~100 行），暴露两个内部接口（只听局域网）：

| 接口 | 作用 |
| --- | --- |
| `POST /api/body/talk` `{ text }` | 走 `brain.reply(text, { peer: 'hw:pi', ... })`，返回她要说的话。`peer: 'hw:pi'` 是个独立对话，有自己的聊天记录和 5 天上下文，跟 QQ 各聊各的但共用记忆和人设 |
| `POST /api/body/look` `{ image(base64) }` | 走现有 `llm.seeImage()`，返回她看到的描述 |

Pi 侧收到 `talk` 的回复后，本地用 edge-tts 合成 Meijia 音频直接播放。这样：

- QQ 聊天、群聊、桌面硬件 = 三个「嘴巴」，一个脑子；
- 她在桌上说过的话会进她自己的记忆流水线（日结/印象照跑）；
- 面板里照旧能看她今天说了什么。

**安全注意**：身体桥只绑局域网，最好加个简单 token（面板已有 secrets 机制可复用），别暴露公网。

## 五、落地路线（建议分三步）

1. **第一步：能说话（1~2 个晚上）**
   Pi 装 Bookworm → Python 环境 → sherpa-onnx 唤醒+识别 → panel 加 `/api/body/talk` → edge-tts 播报。
   验收：喊「肥鱼」→ 说话 → 她用 QQ 里那个声音回你。
2. **第二步：能看（1 个晚上）**
   接摄像头 → `/api/body/look` → 对话里说「你看这是什么」时自动附一张当前画面。
   验收：举张图问「这上头写的啥」，她答得上来。
3. **第三步：像个摆件（慢慢玩）**
   加一块小圆屏当「脸」（表情包直接派上用场）；加个舵机/氛围灯；本地命令词（「闭嘴」「睡觉」直接静音，不惊动大脑）；断网降级。

## 六、备选方案：不自己攒，用现成硬件终端

如果目标只是「有个实体能跟她语音聊」，可以看看开源项目 **小智（xiaozhi-esp32）** 这类 ESP32-S3 语音盒子（整机 ￥100~200）：

- 优点：便宜、固件成熟、唤醒+拾音+播报全做好了，社区活跃；
- 缺点：**没有摄像头/视觉**（少数带摄像头的型号也很弱），而且它的对话服务要自己搭/接，接进咱们这套得写适配层；性能上限低。

结论：想要「看 + 听 + 说」完整体验 → 树莓派方案；只想低成本语音对话 → 小智类盒子可以当补充终端。两者不冲突，以后甚至可以都接进同一个身体桥。

## 七、已知的坑

- **回声**：喇叭声音被自己麦克风收进去 → 她自己说话时要「半双工」（播放期间暂停识别），这是桌面语音机器人最常见的坑，第一版就按半双工做；
- **供电**：Pi 5 + 摄像头 + 功放对电源要求高，杂牌电源会出现随机死机/摄像头掉线；
- **网络依赖**：大脑在局域网 NAS 上，NAS 挂了她就「发呆」（唤醒有反应但答不上来）；断网要有句兜底的话术（「我脑子有点晕，等会儿再聊」）；
- **麦克风阵列**：3 米外远场唤醒对 ¥100 级的麦有点勉强，预期放在 1~1.5 米内效果最好；
- **token 成本**：桌面端对话比 QQ 更容易一句一句聊，聊得越多调用量越大，跟「群里插嘴」那件事同理。
