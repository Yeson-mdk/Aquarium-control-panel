## 1. 数据层（零改 store.mjs）

约定就是 tasks.jsonl 的一条，type 用 `'appointment'`：
```jsonc
{
  "id": "...", "ts": "2026-11-17T...", "type": "appointment",
  "status": "pending",           // pending → fired / cancelled / expired
  "executor": "bot", "source": "auto",
  "dueAt": 1731798000000,        // 新增：到点时间戳（ms）
  "peer": "g:9003",              // 新增：回哪个会话（'owner' / 'g:群号' / 'p:QQ号'）
  "originText": "明天9点找我",   // 新增：当时对方原话（赴约上下文 + 日志可追溯）
  "originMsgId": "msg_xxx",      // 新增：依据消息id（防扯皮）
  "who": "卷心菜",               // 新增：谁约的（群里有同名时定位用）
  "note": ""                     // payload 不用，note 留给面板显示
}
```
落库：`addTask({ type:'appointment', executor:'bot', dueAt, peer, originText, originMsgId, who })`——addTask 现成签名能接（payload/note 传空）。读：`readTasks().filter(t => t.type==='appointment' && t.status==='pending' && t.dueAt<=now)`。改状态：`updateTask(id, { status:'fired', firedAt: nowIso() })`。**store.mjs 一个字不改。**

## 2. 识别层（新建 `qq/appoint.mjs`，两条入口）

### 入口A 号主明说设闹钟（人设风险极低，不过指向判定）
- `qq/tools.mjs` 加 `set_appointment` 工具（号主专用，进 `toolDefs` 不进 `PUBLIC_TOOLS`）
- brain.reply 的工具分发里加 case：号主说"明早8点叫我"→ 模型调 `set_appointment`→ 工具函数把"明早8点"算成时间戳 → `addTask` 落库
- 时间解析：LLM 在工具参数里直接给 `dueAt`（ISO 字符串或时间戳），程序侧校验合法 + 不在过去 + 不超 7 天

### 入口B 别人约她她赴约（照 digestGroup 抄，核心）
- `qq/appoint.mjs` 新 export `scanForAppointments(peer, { since, now })`
- 夜间链或低峰时段扫当天聊天（照 digestCandidates 范式取活跃对话）：
  - readChat(peer) → 只要别人说的 + 指向她的（复用 brain.mjs:242 direct 正则）
  - llm.chat 抽取（带 PERSONA + 事实约束）：
    ```
    输入：指向她的句子（带说话人、带原话、带当前时间做参照）
    输出：{"appointments":[{"text":"对方约的原话","dueAt":"ISO时间","who":"说话人","msgId":"依据"}]}
    只抽含明确时间或明确事件的约定；没约定给空数组；时间算不准的不抽
    ```
  - looseJson 解析 + 时间戳校验（非法/在过去/超7天 丢弃）+ msgId 校验（必须在原文里）
  - 每条 addTask 落库
- 挂哪：照 maybeReflect 的 reflectHour 闸，挂夜间链（qq/index.mjs 夜间那段）或 autopilot tick 低峰；**不挂每条消息落库时**（那样每条聊天都烧一次模型）

## 3. 触发层（autopilot tick 加扫描）

`autopilot.mjs:158` `notify.flushPending` 之后加一行：
```javascript
scanDueAppointments(now).catch((e) => console.error('[autopilot] 约定赴约', e.message));
```
`scanDueAppointments` 在 `qq/appoint.mjs` 里：
- `readTasks().filter(t => t.type==='appointment' && t.status==='pending' && t.dueAt<=now && now-t.dueAt<3600000)`（过期超1小时不发）
- 每天最多兑现2条（`todayCounts().appointment >= 2` 挡，照 planTypeBlocked 范式——需 store.mjs 的 todayCounts 认 appointment kind，logAction 时 kind 写 'appointment'）
- 逐条 `fulfillAppointment(a)`

---

## 4. 发送层（分两条路径，都在 `qq/appoint.mjs`）

### 号主闹钟（peer='owner'）
- llm.chat 生成她的一句话（PERSONA + "到点提醒号主：originText" 语义）
- `notify.rawSend(text)` 直发（不过仲裁，号主亲口要的风险低）
- `updateTask(id, { status:'fired', firedAt })`

### 赴约（peer='g:'/'p:'）
- 上下文 = `originText`（对方原话）+ `friends.recentSocial(peer)`（跟这个人的近期记忆）
- llm.chat 生成她的一句话（PERSONA + "赴约：对方约你 originText，到点了主动说一句" 语义 + 防串场约束"只聊跟这个人有关的事"）
- `qq.sendText(text, 'appointment', peer)` 发回原 peer（sendText 自动 logChat、自动剥 [TO:] 转 @）
- `updateTask(id, { status:'fired', firedAt })`
- ⚠️ **不过 brain.reply 的 reviewJoin 仲裁**：reviewJoin 是"要不要加入对话"的闸，赴约是"到点主动开口"语义不同。"过仲裁人设检查"靠 llm.chat 带 PERSONA 系统提示实现——让她写的话符合人设，但不走"回话"管线（没有触发文本可回）

---

## 5. 护栏（照设计 + 现有范式）

- **每天最多兑现2条**：scanDueAppointments 里 `todayCounts().appointment >= 2` 挡（logAction kind 写 'appointment'，todayCounts 自动计数）
- **过期超1小时不发**：scanDue 的 `now-t.dueAt<3600000` 过滤；超了的标 `status:'expired'` + 写一条记忆（待决点①选 a 的话）
- **识别抽取挂低峰**：scanForAppointments 不挂每条消息，挂夜间链（照 digestGroup 的调度范式）
- **识别开关**：`config.appoint.enabled`（默认关，照 morningPlan 范式），面板有开关
- **坏 JSON 不炸**：looseJson 返回 {} → 空数组 → 不落库（照 digestGroup）

## 7. 落地顺序建议

照上一轮讨论，**一次性做完比分两步干净**（底层共享，分开做要数据迁移）：

1. **数据层 + 触发层 + 发送层**（1晚）：新建 qq/appoint.mjs 的 scanDue + fulfillAppointment，autopilot tick 接一行。这步做完**号主明说设闹钟**能手动跑通（识别层先用 tools.mjs 的 set_appointment 临时接）。
2. **识别层 + 面板 + 测试**（1.5晚）：scanForAppointments（入口B别人约她）+ 面板约定栏 + test/appoint.test.mjs。这才是完整阶段三.5。

## 8. 待决点（动手前选，照设计不变）

1. **过期了怎么办**：a) 放弃 + 写进她自己的日记式记忆（「忘了赴约」也是人设） b) 晚到也补一句「抱歉刚看到」——**倾向 a**（人设更真实，b 容易变成无意义打扰）
2. **识别的指向判定用哪档**：只认叫她名字/回她的话（准但漏），还是加「明显在对她说的语境」（全但可能误识别）——**倾向先紧后松**（先复用 direct 正则，漏了不亏，误识别才烦）
